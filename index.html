English Lab ― 作り方の案内　版 001（2026-10-28）

自分専用の英語学習アプリを、
AI と作る

自分の仕事に関わる海外の動画や記事を集め、そこから英語を学ぶ道具を、プログラムを一行も書かずに作りました。AI（Claude）に日本語で頼み続けただけです。何をしてくれるアプリか、何を使ったか、どの順番で頼んだかを、必要な分だけ書きます。

私は歯科医師なので、例は「学会」と「論文」になっています。アパレル・飲食・小売・不動産、どんな仕事でも同じ作りで動きます。海外の展示会・商談会・交流会・コンテスト、そして YouTube にあふれているその分野の動画が、そのまま教材になります。

1何をしてくれるか

部品何をするか自分がすること
集める関心分野を登録しておくと、毎週日曜の夜に YouTube の動画と、その分野の記事や論文の新着を AI が探して採点し、合格したものだけ週報にする関心分野を話す
抜き出す合格した動画の字幕・記事の要旨から、現場で実際に口にする英文と単語を作る。和訳と発音記号つき「単語帳に入れる」を押す
練習する単語ドリル・シャドーイング（発音を点数で評価）・忘れたころに出る復習・車で聞く音声毎日 10 分
話す自分の場面（学会の質疑応答・展示会のブース・商談・交流会など）を AI 相手に声でロールプレイ。詰まったら日本語で言ってよく、「こう言えばよかった」が単語帳に入る話す

「完成」ではなく、毎週少しずつ育っています。4月に始めて、いまが 7 か月目です。

2使ったもの

役目道具ひとこと
話し相手Claudeブラウザとスマホのアプリ。有料プラン（月 20〜200 ドル）が要ります。無料プランでは次の Claude Code が使えません
手を動かす係Claude Code自分のパソコンの中でアプリを組み、置き、直す。同じ契約で使える。Claude のデスクトップアプリ（Mac・Windows）に入っているので、黒い画面を開く必要はない
置き場所Vercel・Supabase・GitHub無料枠。設定は全部 AI がやり、自分はログインだけ
AI の部品OpenAI（会話・講評・読み上げ）・Azure（発音の点数）使った分だけ。Claude の契約とは別払いで、最初に前払い（OpenAI）とカード登録が要る。指示文は OpenAI と Azure の 2 つに絞ってある

持ち物が違っても、できます

パソコンとスマホが 1 台ずつあれば足ります。この文書は Mac と iPhone で進めた記録なので、同じ組み合わせがいちばんそのまま使えます。Windows や Android でもできます。やり方が少し変わる所は、Claude Code に「私は Windows です」「スマホは Android です」と伝え、ご自身で Claude Code に聞きながら進めてください。たとえば次の 2 点です。

  • Windows：週 1 回の自動実行を、Mac の予約機能ではなく「タスク スケジューラ」で組む
  • Android：音声入力の癖が iPhone と違う（むしろ素直で、手間は少ない）

3どの順番で頼んだか

1まず文章で試す（1 日目）

Claude に「自分の仕事で使う英語表現を 20 個」と頼む。アプリの前に、AI が自分の分野を扱えるかを確かめる。

頼み方：「私は〔仕事：例 歯科医師／アパレルのバイヤー／飲食店の経営者〕です。〔場面：例 国際学会の質疑応答／海外の展示会での商談／外国人のお客様への接客〕で使う表現を、私の実際の仕事に合わせて作って」

2設計書を書かせる（1 週目）

いきなり作らせない。「自分だけが使う英語学習アプリの設計書を書いて」と頼み、読んで「ここは要らない」「これが欲しい」を返す。私の設計書は、学会・実務・私的・診療の 4 分野で単語を色分けする、という一点から始まった。

頼み方：「設計書を書いて。私が読めるように、専門用語は使わないで」

3Claude Code に組ませる（2〜4 週目）

Claude のデスクトップアプリを入れて「Code」のタブを開き、設計書を渡して「作って」。動いたらスマホで触り、「ここが変」と言う。これを繰り返す。自分がしたのは Vercel・Supabase・GitHub へのログインだけ。

頼み方：「設計書どおりに作って、スマホで使える形で公開して。本番に出す前に必ず私に確認して」
つまずいた所
  • 「動きました」を信じて自分の目で見なかった → 9 日を失った。必ず実機で触る
  • 無料枠のデータベースは、しばらく触らないと眠る → AI に毎日 1 回読みに行く見張りを作らせた
  • YouTube の字幕は、クラウドからは取れず自宅の Mac からしか取れなかった → 収集だけ Mac で週 1 回自動実行

4育てる（2 か月目〜）

使って「言えなかった」「字幕が無い」と感じたことを、そのまま AI に言う。会話練習で詰まった表現が自動で単語帳に入る仕組みも、論文から英文を作る仕組みも、全部あとから足したもの。

頼み方：「きのうの練習で言えなかった表現を、自動で単語帳に入るようにして」

4遠回りしない 3 つ

1．「できる？」ではなく「やって」と言う。説明ではなく、結果が返ってくる。
2．自分の手を使うのは、ログイン・支払い・実機で試す・最終判断の 4 つだけ。それ以外は「あなたが先に試して」。
3．本番に出す・お金を払う判断は、毎回自分が押す。ここを預けなかったことが、安心して任せられた理由。

5お金

Claude の有料プラン（月 20〜200 ドル）。アプリの AI 部品は使った分だけで月数百円ですが、最初に OpenAI の前払い（数ドルから）と、Azure のカード登録が要ります。置き場所は無料枠で 0 円。Pro プランには「数時間使うと、○時まで休み」という上限があり、出ても壊れていません。待てば戻ります。

6Claude Code にそのまま貼る指示文（汎用版）

「設計書を書いて」から始めると途中で止まりがちなので、枠組みのヒントを先に渡すための文です。Claude Code を入れたら、最初の会話にこれを貼ってください。Mac でも Windows でも、iPhone でも Android でも、同じ文で足ります。パソコンの種類は AI が自分で見分け、スマホの種類だけ最初に 1 回聞いてきます。〔　〕の中だけ自分のことに書き換えます。

指示文（コピーして貼る）
あなたは、プログラムを書けない私（〔仕事：例 歯科医師／アパレルのバイヤー／飲食店の経営者〕・扱う分野は〔　〕）の
「自分専用の英語学習アプリ」を、設計から公開まで一緒に作る相棒です。
私はコンピュータの初学者です。専門用語を使わず、番号つきで 1 回に 1 つだけ聞いてください。

■ 最初に、この 3 つだけ私に聞いてください（1 つずつ）
1. 仕事の分野と、英語を使う場面（学会・展示会・商談・接客・交流会など）
2. スマホは iPhone か Android か（パソコンの種類は聞かず、あなたが確かめる）
3. AI の部品に月いくらまで払ってよいか（目安は月 500〜1,500 円）
聞き終わったら、設計書の目次を出してください。

■ 私の環境（あなたが見分ける）
- パソコンが Mac か Windows かはあなたが確かめる。アプリの置き場所は iCloud Drive や OneDrive の外（例：ホーム直下の Projects）
- Mac：週 1 回の自動実行は launchd。Windows：タスク スケジューラ、コマンドは PowerShell、文字コードは UTF-8 を明示。
  どちらも「その時刻にパソコンが起きていないと動かない」ことを設計書に書く
- iPhone：Safari の音声認識は continuous=false で、無音をこちらの時計で区切る。Android：Chrome は continuous=true が使える
- どれに当たっても、私への説明は「スマホ」「パソコン」の言葉で書き、違いは内側で吸収する

■ 作りたいもの（1 つずつ順に作り、各段で私がスマホで触って確かめます）
0. 準備：公開の置き場所（GitHub・Vercel・Supabase）へのログインを、段階 1 の前にまとめて済ませる
1. 単語帳とドリル：英文・和訳・発音記号・例文。忘れたころに出てくる復習つき
2. 動画から学ぶ：YouTube の URL を入れると字幕を取り、単語と言い回しを拾って単語帳へ
3. 話す練習：〔例：学会の質疑応答／展示会での商談／お客様への説明〕の場面で AI と声でロールプレイ。
   言えなくて日本語で言った所は「こう言えばよかった」として単語帳に入る
4. 自動で集める：関心分野〔例：　〕の新しい YouTube 動画と記事（学術分野なら論文）を週 1 回探して採点し、合格だけ一覧にする。
   どのチャンネル・サイトを見るかは、設計のときに私に 3 つ挙げてもらう

■ 進め方の約束
- いきなり作らない。まず設計書を私が読める言葉で書き、私の「はい」を待つ
- 1 段できるたびに、私がスマホで開ける URL を出し、「どこを押して何が見えれば成功か」を書く
- 自分で調べれば分かること（パソコンの種類・入っている道具・エラーの原因）は自分で調べ、私に聞かない。
  私の判断が要るときだけ、おすすめを 1 つ付けて 1 回に 1 つ聞く
- 技術の選択はあなたが決め、「こう決めました。理由は〜」と 1 行で報告する
- 「動きました」とだけ言わない。何件・いつ・どの画面で確かめたかを添える
- 本番に出す・お金がかかる・消す・外へ送る操作は、先に文面と金額を見せて私の「はい」を待つ
- 私がやるのは、ログイン・支払い・スマホで試す・最終判断の 4 つだけ。それ以外はあなたが先に試す
- 有料サービスは無料枠か前払いで始める。サービス側に月の上限の設定があれば、その画面への道順を私に案内する
- 患者さん・お客様の情報は一切入れない前提で設計する
- プロジェクトの中に「進み具合.md」を置き、段が終わるたびに「どこまで済んだ・次に私がすること」を書き直す。
  新しい会話で「続きをやって」と言われたら、まずそれを読む

■ 私が止まったときの合図（この言葉が来たら、こう動く）
- 「続けて」→ 止まっていた所から再開する
- 「おすすめで」→ あなたのおすすめで決めて進む
- 赤い字やエラーを貼って「直して」→ 原因を 1 行で言い、直して、確かめてから報告する
- 「いまどこ？」→ 進み具合.md を読み、「ここまで済んだ／次に私がすること 1 つ」を答える
- 「何も見えない」→ URL と、押す場所と、見えるはずの画面を、もう一度書く
- 許可を求める画面で私が困っていたら、「Yes（はい）を選んでください。危ないものは私が先に止めます」と伝える
- ログインや鍵の発行が要る場面では、最初に「ここは私の手が要ります。正常です」と言い、
  開くページの直リンク・押すボタン・終わったら何と言えばよいかを書く

■ 鍵の扱い
- 鍵や合言葉は .env.local に置き、画面にも会話にも出さない
- ログインで取れる鍵（Vercel・Supabase・GitHub）は、それぞれの道具のログインであなたが取りに行く。私に貼らせない
- 貼るしかない鍵（OpenAI・Azure）は、あなたがメモ帳の窓を開き、私がそこに貼って保存する。会話には貼らせない

■ 技術のヒント（私は理解しなくてよい。あなたの判断に使う）
- 形：スマホのホーム画面に置いて使う Web アプリ（Next.js）。ストアには出さない。iPhone でも Android でも同じもの
- 置き場所：GitHub（保管庫）＋ Vercel（公開）＋ Supabase（データ）。いずれも無料枠から
- AI の部品は少なく：会話・講評・採点・読み上げは OpenAI の 1 つで。発音の点数は Azure Speech（無料枠）。
  動画の検索は YouTube Data API（無料枠）。それ以外は増やさない
- 音声入力はブラウザの音声認識。読み上げは複数の音声サービスを切り替えられる作り
- ログインは 1 人用のいちばん簡単な方法（合言葉か、メールのワンタイムコード）。Google ログインは使わない
- YouTube の字幕はクラウドから取れないことが多い。取得は私のパソコンで行い、データベースへ直接入れる。
  「取れなかった」と「字幕が無い」を区別して記録する
- 週 1 回の自動収集はパソコンの予約機能で動かし、動いた記録（日時・件数）を毎回残す
- 無料枠のデータベースは放置すると眠る。毎日 1 回読みに行く見張りを最初から入れる

★ これは「枠組み」です。私のアプリと同じものにはなりませんし、ならなくて構いません。相手の専門・端末・予算に合わせて、AI が設計書を変えてきます。

それでも、必ず何度か止まります。大半は「壊れた」のではなく「人の手が要る場面」です。止まったときの見分け方と、言う言葉を 1 枚にまとめました。

困ったときの手引き → 止まったとき、壊れたと思ったときに開くページ
